# Отчёт

## 1. Постановка задачи
Целью данной работы является исследование изменений свойств цифровых изображений при внедрении скрытых данных методом наименее значимого бита (LSB), а также сравнительный анализ трех вариантов сокрытия информации с помощью статистических показателей и метрик качества

В ходе исследования реализованы и сопоставлены следующие три варианта:

1. **Plain LSB** - встраивание открытого текста путем последовательного обхода пикселей контейнера

2. **Encrypted LSB** - встраивание зашифрованного текста (с использованием симметричного шифрования AES-GCM и производной функции ключа PBKDF2) последовательным обходом

3. **Encrypted Random LSB** - встраивание зашифрованного текста в псевдослучайные позиции, определяемые по ключу-паролю без повторений

**Используемые изображения:** В качестве основного контейнера в эксперименте использовалось пользовательское изображение `akashi.png` 

**Встраиваемое сообщение:** В качестве основного payload использовалась тестовая строка: `"Ералаша не забудем"`

## 2. Реализация

### 2.1. Обычное LSB-встраивание
Встраивание выполняется путем замены младшего бита цветовых компонент (R, G, B) пикселей изображения битами полезной нагрузки. Изменение значения компоненты составляет строго pm 1 или 0

Реализация из `lsb.py`:
```
def embed_data(image_path: str, output_path: str, data_bytes: bytes, password: str = None, random_pos: bool = False):
    img = Image.open(image_path).convert('RGB')
    width, height = img.size
    max_capacity_bits = width * height * 3

    # Пакет данных: [4 байта общей длины] + [данные]
    full_data = len(data_bytes).to_bytes(4, 'big') + data_bytes
    total_bits_needed = len(full_data) * 8

    if total_bits_needed > max_capacity_bits:
        raise ValueError(f"Ошибка: Сообщение слишком большое. Требуется {total_bits_needed} бит, доступно {max_capacity_bits}.")

    bits = [(b >> i) & 1 for b in full_data for i in range(7, -1, -1)]

    flat_channels = []
    for p in img.getdata():
        flat_channels.extend(p)

    # Логика встраивания (последовательная или псевдослучайная)
    if random_pos:
        pass_hash = hashlib.sha256(password.encode('utf-8')).digest()
        rng = random.Random(int.from_bytes(pass_hash, 'big'))
        indices = list(range(max_capacity_bits))
        rng.shuffle(indices)
        chosen_indices = indices[:len(bits)]
        for bit_idx, pos in enumerate(chosen_indices):
            flat_channels[pos] = (flat_channels[pos] & ~1) | bits[bit_idx]
    else:
        for idx, bit in enumerate(bits):
            flat_channels[idx] = (flat_channels[idx] & ~1) | bit

    new_pixels = [(flat_channels[i], flat_channels[i + 1], flat_channels[i + 2]) for i in range(0, len(flat_channels), 3)]
    res_img = Image.new('RGB', (width, height))
    res_img.putdata(new_pixels)
    res_img.save(output_path, 'PNG')
```
### 2.2. Хранение длины и проверка вместимости
**Длина сообщения**: Для корректного извлечения первые 4 байта (32 бита) контейнера выделены под запись общей длины полезной нагрузки в байтах (int.to_bytes(4, 'big'))

**Вместимость**: Перед началом работы емкость контейнера проверяется по формуле capacity = width * height * 3

### 2.3. Шифрование сообщения
Перед внедрением в гибридных вариантах текст шифруется с помощью AES-GCM. Ключ длиной 32 байта генерируется из пароля через PBKDF2HMAC  с добавлением случайной соли (16 байт) и вектора инициализации (12 байт)

Реализация из `lsb.py` :
```
def encrypt_message(password: str, secret_text: str) -> tuple[bytes, bytes, bytes]:
    salt = os.urandom(16)
    nonce = os.urandom(12)
    kdf = PBKDF2HMAC(algorithm=hashes.SHA256(), length=32, salt=salt, iterations=100_000)
    key = kdf.derive(password.encode('utf-8'))
    
    aesgcm = AESGCM(key)
    ciphertext = aesgcm.encrypt(nonce, secret_text.encode('utf-8'), None)
    return salt, nonce, ciphertext
```

### 2.4. Псевдослучайный порядок позиций - Random LSB
Для распределения изменений по всему изображению хэш пароля (SHA-256) используется в качестве зерна (seed) для генератора random.Random. Метод rng.shuffle(indices) формирует уникальную последовательность индексов каналов без повторений

## 3. Методика эксперимента

Объём данных: В ходе основного эксперимента применялось короткое сообщение (payload малого объема, занимающее <0.01% емкости)
Для оценки влияния роста данных (пункт 13) дополнительно исследовался большой объем (payload более 8 Кб)

Рассчитываемые метрики:
1) PSNR (Peak Signal-to-Noise Ratio) и SSIM (Structural Similarity Index) - оценка визуального искажения
2) Changed ratio - доля измененных цветовых компонент
3) Распределение LSB — доли единиц и нулей (P(LSB=0) и P(LSB=1)) χ²-статистика и p-value - анализ частот пар яркостей (2k, 2k+1) для оценки обнаружимости

## 5. Анализ

В данном разделе проводится сопоставление результатов, полученных для всех трех вариантов стеганографических преобразований (`Plain LSB`, `Encrypted LSB`, `Encrypted Random LSB`), с целью оценки их эффективности, скрытности и статистической стойкости

### 5.1. **(PSNR и SSIM):**
  Значения Пикового отношения сигнала к шуму (PSNR) для всех вариантов находятся в диапазоне 85 - 88 dB, а индекс структурного сходства (SSIM) равен 1.0000
  *следовательно:* 
  Визуальные искажения полностью отсутствуют. Разница между исходным изображением и стего-контейнером лежит далеко за пределами порога восприятия человеческого глаза. Гибридные методы имеют незначительно меньший PSNR за счет добавления служебных криптографических полей (`salt`, `nonce`), но качество остается идеальным

### 5.2. **Доля изменённых компонент (`changed_ratio`):**
 Для исследованного короткого сообщения доля измененных цветовых компонент составила 0.01% - 0.02%. Это означает, что модифицирована лишь малая доля от общего массива пикселей изображения (RGB-каналов)
 *следовательно:* 
 Объем изменений строго пропорционален размеру полезной нагрузки и служебных данных, что минимизирует риск обнаружения методами пространственного анализа

### 5.3. - 5.4. **Распределение LSB и χ²-статистика:**
 В исходном изображении (`Cover`) распределение младших битов имеет естественный статистический дисбаланс, обусловленный особенностями генерации или оцифровки (χ² = 20937.21)
 После встраивания данных псевдослучайный поток битов стремится выровнять частоты появления нулей и единиц. Однако при малом объеме полезной нагрузки глобальное значение χ²-статистики меняется незначительно, сохраняя общую структуру контейнера

### 5.5. **Влияние шифрования:**
Использование симметричного шифрования **AES-GCM** перед внедрением полностью маскирует семантику исходного текста. Шифротекст обладает высокой энтропией и неотличим от случайного шума, что защищает данные от несанкционированного извлечения даже при обнаружении факта наличия стегоконтейнера

### 5.6. **Влияние псевдослучайного размещения (Random LSB):**
Последовательное встраивание (`Plain / Encrypted LSB`) изменяет пиксели подряд, начиная с левого верхнего угла, что потенциально может быть обнаружено специализированными детекторами
Псевдослучайное распределение (`Encrypted Random LSB`), инициализированное хэшем пароля, «размазывает» изменения по всей матрице изображения хаотичным, но воспроизводимым образом. Это эффективно разрушает локальные кластеры артефактов и защищает от простого последовательного извлечения

### 5.7. **Влияние роста полезной нагрузки (Payload):**

При увеличении объема скрываемых данных доля измененных компонент (`changed_ratio`) линейно возрастает. Это приводит к заметному падению PSNR и резкому отклонению статистических характеристик (χ²-критерия) от исходного контейнера, делая стегосистему уязвимой для методов стегоанализа
